# Explicit junctions and net labels

Junctions and net labels are single-node schematic primitives in the component tray. Place them, connect their terminal dots, move/rotate, duplicate, delete and undo through the same ordinary user/agent commands as components. They add no electrical load or physical device model. All drawing objects share the existing 50-object/150-wire limits.

A connected junction's filled dot represents an explicit join; an unwired placed junction remains a hollow terminal and Incomplete. Selecting a connected wire offers **Insert junction on this wire**; it chooses a free interior grid point and splits that wire as one undoable operation. The junction placement tool also inserts on a single nearby route. At a visual crossing it leaves the graph unchanged, updates the X/Y placement draft, and asks the user to review the named targets. **Join named routes at X/Y** explicitly joins the displayed routes. Unjoined crossings and near misses never connect.

`wire.junction.insert {wire_ids:[...],id?,position?}` is the shared operation. It accepts 1–8 unique connected wire IDs. An explicit position is required for multiple wires; a single wire can choose its default interior point. Each named route must pass within half a grid step (5 world units) of the snapped point, and the point must be at least one grid step from existing endpoints. Occupied centers, invalid IDs/positions, disconnected wires, unknown/duplicate targets and capacity overflow refuse before any mutation. Existing wire IDs are retained on their first segment; new IDs identify second segments. All reservations and graph changes form one history operation. The command is also available in `edit.batch`.

A net label has stable object/pin identity (`L1.node`) and a separate editable name. `component.place {kind:"net-label",position,value?}` uses `value` as its name; omission chooses its unique object ID. The placement draft allows a chosen name. `component.set {id,value}` edits it. Names are 1–32 ASCII letters/digits or `_+-./`, without spaces, and match **exactly, case-sensitively**. Duplicate copies retain their label name and intentionally join the named net; blank placement defaults never share an accidental common name.

Labels with the same name connect their attached nets throughout the current single sheet. Different names can describe one explicitly wired net; `snapshot.nets[].labels` reports all sorted unique names. A label named `GND` does not establish a reference by itself: connect it to a ground symbol. Geometry, symbol order, rotation and unrelated object IDs do not create joins. Unattached junction/label nets remain Incomplete, and a helper terminal does not count as a second circuit terminal that could hide an open pin.

Existing LED, RC, NPN, pulse and coupled RC/NPN solvers accept these explicit connectivity paths. Helpers are omitted from physical stamping/device counts. Canonical net IDs prefer physical terminals, and net order remains deterministic, so adding an equivalent junction does not reorder an existing physical network. Moving/rotating a connected helper retains connectivity and does not restart the solver. Renaming a label changes connectivity and restarts live analysis with ordinary incomplete/stale diagnostics when needed.

Primitive voltage probes use `v:<id>.node` and read the actual connected net. Net-label probe captions use the captured label name; IDs stay stable. Recorded input validation, project save/open, recovery and dependency hashes preserve the complete primitive graph. SVG uses the shared wire routes, filled junction symbols and escaped readable label names, with bounds for long label text. The existing file versions remain current: optional component `label` data is validated only for the versioned `net-label.v1` primitive, and earlier unlabeled schematics remain readable.

Validation includes supported-circuit numerical equivalence, mixed transient Verify/primitive-probe equivalence, atomic undo and batch integration, explicit two-route crossing joins, case-sensitive remote labels, open-pin/reference diagnostics, project/record persistence, SVG text, and native/agent placement/edit parity. Native pointer tests require crossing review before joining. The actual GPU/UI smoke builds and renders a junction and named supply through ordinary controls. `scripts/primitives-demo.py` provides headless and owned-desktop regression workflows.

This adds connectivity primitives; it does not claim general analog/SPICE topology coverage, PCB interchange, hierarchical/global multi-sheet labels, or automatic connection based on geometry. Those remain separate scope/validation work.
