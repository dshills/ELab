# Atomic edit batches and history

Filtered `capabilities.list` supplies `atomic-edits-and-history` contracts for `edit.batch`, `edit.undo` and `edit.redo`. Ordinary discovery/output schemas and public command IDs remain unchanged. The native history shortcuts and agents use the same guarded service.

`edit.batch` requires a non-null name of 1–80 UTF-8 bytes, not all whitespace, and 1–100 edits. Names retain surrounding whitespace. Each child has a supported command and non-null parameter object in that command's grammar. Discovery publishes all 17 supported IDs from the same allowlist used by validation; query each child's detailed capability for its fields/quantities. Children have no separate protocol envelope, revision guard or retry key. File work, queries, run controls, history, nested batches and general experiment/pin/display setters are outside this allowlist.

Edits run in order on cloned graph/settings/drawing/selection/ID reservations. Later edits can refer to earlier explicit IDs and staged values. Each intermediate edit must be structurally valid, while an incomplete or unsupported electrical drawing can still be edited. A failed child discards the entire staged result and its new ID reservations without affecting public state, history, physics or files. Child failures identify their 1-based index.

A changed final graph/settings commits once, adds one named actor/revision-attributed undo entry and clears redo. Electrical changes follow normal startup/paused stale behavior; geometry-only changes preserve accepted physics. Switch/wiper children are startup configuration rather than live queued actuation. Sampling Fit and timing convenience commands use preceding staged values/settings.

An unchanged final graph/settings adds no history entry and preserves redo/accepted physics, but still advances command revision. It can consume IDs for objects created and deleted within the successful batch. Selection and drawing references normalize against the final staged graph, including when graph equality skips ordinary document-change cleanup. This repairs a reproduced dangling selection after create/delete without changing graph, history, ID reservation or physical state.

Undo/redo inspect `snapshot.undo_entry`/`redo_entry`. Their `command_revision` identifies the original entry, not the latest command. Optional omitted/null `expected_entry_revision` adds no extra guard; zero is an actual comparison. A supplied value must match before cross-actor acknowledgment is considered. Optional omitted/null/false `allow_other_actor` refuses another actor's tip; true acknowledges it while preserving all ordinary context checks. Empty stacks return `unavailable`, mismatched/unacknowledged tips return `history-conflict` and malformed input returns `invalid-params` without changing state.

History restores graph, transient settings, pins, display and example contents, retaining original entry name/actor/revision through undo and redo. It does not restore file association/baselines, document generation, kept assets, viewport, pause, selection/drawing or numerical time/charge. Drawing references normalize after changed contents. Undoing New/Open does not reassociate the old path or restore cleared recordings. Pending input work is canceled; electrical differences restart or become paused stale through the usual rules, while presentation changes preserve accepted readings. History is session-local, bounded to 100 undo entries and not loaded from files.

Dirty flags compare contents with the latest Save baseline. Undo can therefore make a recently saved document dirty, and redo can make it clean. Successful retries return their original owned snapshot before new guard checks; retrying a batch after undo must not reapply it. Inspect again for current state.

[Combined SDK/batch qualification](validation/vellum-refresh-validation.json) retains the failing regression, repair, pure refusals, committed/rejected ID behavior, UTF-8 boundary, exact-tip history, latest baseline, retry and unchanged captured-data checks through headless/native interfaces. Controlled tests separately cover other actors and pending work. This is not complete physical shortcut/accessibility or visible-latency qualification.
