# Mixed-solver matrix work

This source cleanup follows the repeated mixed-solver time-budget failures in instrumented default package tests. The existing controlled audit already demonstrates that scheduler pressure can produce a classified, state-preserving failure; neither the historical failures nor this cleanup establish a unique cause. Production limits remain 512 adaptive attempts and a cooperatively checked 100 ms wall budget. No test deadline, model, convergence tolerance, stepping rule or command is relaxed.

An owned one-CPU baseline profile of the doubled-capacitance flasher attributes about 85% of sampled allocation objects to `mnaEquations`. Capacitor-only Newton matrices allocated each row separately, while the inductor path already used disjoint rows backed by one value allocation. The same allocator now lives in `mixed_matrix.go` and serves both paths. Every matrix is private to its solve; rows have capacity-limited spans, and there is no pool or shared mutable workspace.

The assembly fixture drops from 10 allocations to 3, consistently across three 10,000-iteration runs, at the same 768 bytes per assembly. Two 600-sample flasher variants drop from roughly 912,000 to 399,000 allocation objects, including result serialization. Total bytes remain roughly 72.6 MB per fixture. Assembly timing ranges overlap; the one-run-per-variant whole-fixture timings do not demonstrate a speedup. These data establish reduced object churn, not an elapsed-time, visible-latency or p95 improvement.

All 600 accepted unknown/storage/result records for each capacitance variant have the exact same digest before/after on this recorded toolchain. Both retain 1,116 adaptive attempts, with a peak of 36 per output sample. The numerical comparison benchmark uses the existing test clock to avoid scheduler-dependent output truncation; it retains the production attempt limit. Separate real-clock idle/pressure audits and deadline/attempt failure tests exercise the unchanged time guard.

## Large matrices

The allocator-only development public run failed its capacity RC/MOSFET Verify at the unchanged 100 ms limit. A preserved /171 baseline subsequently passed the same broad workload and 480 real-clock coil timing samples across three backend adapters. An isolated 200-output capacity diagnostic gives identical complete accepted-state/trace digests and attempt counts for both allocators: 620 attempts, peak 73. Measured integration work is about 620/622 ms, with roughly 60/58 ms peak outputs. This does not reproduce or identify the cause of that public timeout, and the failure remains evidence.

That 61-unknown case exposed a separate cost: ordinary Gaussian elimination updated every zero coefficient. The inductor solver already omitted zero updates while retaining pivoting and nonzero update order. The final ordinary solver reuses that path at 16 or more unknowns. Three 10,000-iteration sparse-ladder trials at sizes 4/8/16/32/61 and complete application fixtures inform the crossover; small flasher runs showed little elapsed benefit from always enabling it and incurred extra scratch allocation. Smaller ordinary systems therefore retain their prior update path.

The final capacity diagnostic retains the exact same 200-output digest and 620/73 attempt counts. On this one recorded run, integration work is 244.971 ms versus 620.329 ms baseline, with a 22.686 ms peak versus 60.073 ms. This is a fixture-specific backend observation, not a cohort p95 or a guarantee against future time-limit failures. All 1,400 accepted records across the two flasher variants and capacity case remain byte-identical. New solver tests compare both update paths and the size-selected path against known solutions for sparse/dense systems through 61 unknowns, including row pivoting, singular matrices and nonfinite inputs.

The capacity benchmark's allocated bytes increase from about 503.6 MB to 528.4 MB (roughly 5%); objects decrease from about 1,004,000 to 234,000. The column list and larger contiguous allocations trade some bytes for less allocation/elimination work. These totals include fixture initialization and serialization, and are not retained-heap measurements.

New race-tested checks cover zero initialization, row growth without neighbor corruption, independent matrices/trials, and a known linear system requiring pivoting. Existing coupled Radau Jacobian, stiff decay, order and deadline-retention cases pass. The intermediate allocator's real-clock idle audit reaches 6 s with the existing period/conservation bounds. Eight owned burners confined to the same test-process CPU still produce `integration-time-limit`, preserving the prior 0.18 s state when the requested 0.19 s sample fails. The observed 211 ms elapsed rejection reflects cooperative checks and scheduling; it is not a promise of preemptive return at 100 ms.

The final size-selected implementation repeats the real-clock audit: idle reaches 6 s and the eight-burner case rejects at the same requested time with accepted state preserved (216.657 ms observed rejection). The final development public run passes the electrical, inductor, op-amp, op-amp/storage and capacity suites across in-process, headless stdio and private headless socket adapters. All 480 real-clock coil timing samples meet their backend targets (20 per case, 79.668 s overall). This run excludes the native adapter and visible input timing.

The final default `./scripts/check.sh` passes in 371.358 s, without package serialization overrides. It covers lint/static checks, all 54 Python tests, root and desktop race/vet checks, and the mounted-control race/vet gate. The 647 Go source hashes remain unchanged through this run. Earlier allocator-only default/public failures and the intermediate serialized pass remain separate evidence; the final pass does not identify their cause or establish general timing reliability.
