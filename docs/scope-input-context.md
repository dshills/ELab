# Scope cursor input context

Native plot clicks now use the immutable context captured when scope geometry was prepared: live run or recorded capture ID, visible interval, active cursor, plot bounds, command revision and document generation. The native callback captures this context before dispatching onto the application owner. It no longer reads a newer selection/window to reinterpret an older click. A remount clears the prepared context and rejects callbacks from its prior mount epoch. Hidden scopes, source-pane replacement and active file decisions refuse pointer work.

The existing shared cursor commands perform the mutation. Live cursor requests use the captured interval plus normal command/document revision guards. Recorded cursor requests additionally pin `operation_id` to the capture the user saw; the service checks that target atomically. Changes made by another actor or background project/record selection cannot silently redirect that cursor. A stale accepted request still follows ordinary retry semantics; it is not executed again.

A drag may advance its expected revision only after its own successful cursor write. This lets repeated pointer moves work before the resulting cursor repaint. A new frame can supply its current prepared axis within that same gesture, but it must retain the capture/run, document and cursor role. An intervening command/selection or invalidated context ends the gesture. Each move remains an ordinary shared command; it does not change circuit physics, time, project membership or history.

## Shared recorded cursor guard

`recording.cursor.set` accepts required `cursor` (`a` or `b`) and `time_s` (numeric seconds or shared unit text), plus optional `operation_id`. With a completed capture selected, a nonempty mismatched ID returns `conflict` without mutation. An absent/incomplete selection returns `not-ready`. Missing/empty ID preserves the older current-selection behavior. Native recorded time fields and plot pointers provide the ID; external agents can do the same. Filter `capabilities.list` for this command to inspect target/time/state requirements and errors.

Time remains within the complete recording's duration, not necessarily its visible interval. Results use nearest stored samples and later/right-hand ties. The scope reports whether the resulting cursor is in its visible interval. No new file format, solver behavior, live cursor semantics or command ID is introduced. Reopening a project assigns fresh local recording IDs, so clients must inspect the selected capture before pinning a new request.

Validation covers a regression where an old plot click wrote into a newly selected capture, stale visible windows, fresh-frame time mapping, own-drag continuity, interruption by another actor, invalidated prepared contexts, current-revision wrong-ID refusal and legacy inputs. The packaged smoke waits for fresh GPU scope readback, rejects the old interval context, then exercises a fresh multi-move cursor gesture while preserving live work. Public [headless/native workflows](../scripts/scope-context-demo.py) check atomic target refusal, units, visible validity, reopened IDs and source/file preservation.

The Vellum adapter publishes preparation on the UI owner before GPU submission and exposes no present-completion callback. This repair binds prepared geometry and event context; it does **not** establish which frame the OS physically displayed at every input instant. Full native event-queue, display timing, keyboard/focus, accessibility and platform lifecycle qualification remain separate gates.
