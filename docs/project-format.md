# Portable projects with recorded results

ELab writes self-contained `.elab` JSON projects using `elab.schematic` version 4. Versions 1, 2 and 3 remain readable; older files have no embedded recordings or saved pause preference. Version 1 receives default transient settings. Version 2 adds settings/startup overrides; version 3 adds selected live probes.

Version 4 adds `paused` and `recordings:{entries,selected_index,viewing}`. Each entry contains the complete `elab.verification` version 1 `data` (captured graph, settings, mode, model/engine identity, original creation/operation identity, final results, probes, exact rows and statistics) plus `model_sha256`. Hashes use canonical JSON for the embedded generic LED/NPN parameters; ideal-device dependencies have immutable versioned IDs, hashed as canonical ID references. These are integrity/version references, not producer authentication or hardware certification.

Only **kept** completed recordings are embedded. Successful Verify and JSON import keep their result by default. The native inspector's **Exclude from project / Include in project** buttons and the shared `recording.keep.set {id,keep}` command control membership. Excluding leaves session replay and export intact. Kept records are protected from eviction. At eight protected recordings, creating/importing another refuses with `record-limit`; exclude one before replacing it. Nothing silently drops saved work.

`document.dirty` covers schematic/settings changes and recording membership. `schematic_dirty`, `recordings_dirty` and `recording_count` distinguish them for users/agents. Completing/importing a recording marks an otherwise saved project dirty without changing live physics or schematic history. Restoring the original kept membership returns to the clean save point. Playback, cursor/probe/window changes and exports do not create recording-content changes. As with saved view/probes, the current pause/viewer selection preferences are captured on explicit save without independently marking the document dirty.

Save refuses while a verification is active, so a completed file never implies pending results were saved. Finish or cancel the job first. New/Open/examples/recovery replacement protect all unsaved schematic/recording changes through the existing shared discard/generation guards. Replacement cancels old verification work, clears the previous project's operations and recording selection, and prevents late worker callbacks from modifying the new project. Runtime operation IDs are never reused.

Open validates the complete project and every embedded recording/hash before replacing anything. Loaded records receive fresh local IDs (`project-record` kind) while original portable metadata/rows stay identical. Imported/project-loaded counters cannot claim association with a current live source. A saved selected record/view opens as recorded data, paused at its first sample. Live simulation creates a new run at time zero and the saved startup conditions; the saved pause preference is respected. Paused DC opens compute a fresh operating point; paused transient opens create a fresh initial sample without advancing time. No previous solver memory, live history, manual source events or playback clock is resumed. Undo retains schematic edits, not recording contents or physical history.

Project files are regular local files at most **8 MiB**, with at most eight recordings, 50 components and 150 wires. Legacy version 1–3 files retain the **256 KiB** bound. Each embedded record retains its own 10-second/1000-output-step/4096-row/six-probe constraints and full interior-step/metadata validation. Invalid UTF-8, duplicate/unknown/noncanonical fields, incomplete data, bad values/models/terminals/hashes and links/special files refuse. Publication uses the existing synced temporary file and atomic replacement/non-clobber path, with external-file conflict detection and directory sync where supported.

Recovery capsules now preserve kept recorded assets and the pause/viewer preferences. They are bounded to 8 MiB plus 16 KiB envelope and keep the existing private-directory/session ownership, integrity/hash guards and two-copy retention. `recovery.inspect` returns validated configuration and recording metadata without unbounded waveform rows; `recovery.samples {id,sha256,recording_index,offset?,limit?}` supplies exact rows in pages (default 100, max 200). The restored project is still an unsaved, unassociated copy for Save As. This supersedes the earlier schematic-only recovery payload.

Validation includes all supported analyses, metadata/row equality across project reopen, model-hash tampering, record-only dirty/unsaved guards, protected capacity, restored membership, legacy readers, fresh paused DC/transient starts, project-replacement cancellation, recovery metadata/pages/full restoration, native file-picker/inclusion parity and actual GPU/UI save/open smoke. `scripts/project-recording-demo.py` proves a fresh process can reopen and inspect the complete saved experiment offline. Physical hardware, power-loss behavior, participant usability and public distribution remain separate gates.
