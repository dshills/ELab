# Preserve recovery data when ownership is unknown

A review of the still-open repeated autosave-timing gate found a safety defect first: the lease reader returned inactive for every read/decode/identity error. A valid capsule owned by a still-running separate session could therefore be removed after its lease was damaged. The first regression reproduces that removal, using only owned generated fixtures.

Ownership now has explicit active/inactive/unknown states. A present but unreadable, malformed, oversized, linked/nonregular, mismatched or invalid-PID lease becomes unknown. Unexpected process-probe failures also remain unknown. Foreign active/unknown ownership prevents dismissal at both preparation and commit, with a false removal outcome; inspection and copy restoration stay available. Current-session deletion and known inactive deletion retain their behavior. Missing leases retain the existing graceful-close protocol; arbitrary hostile writers are not covered by a conditional-unlink promise.

Public candidate and inspection/read metadata exposes an enum. The older `active_session` flag remains conservatively true for unknown, so existing clients do not interpret it as safe to delete. Native choices explain “owner not verified,” keep Restore as a new copy available and disable Dismiss. A native test initially inspected selector Options after macOS adaptation; the final test checks the rendered selector title as well as portable options.

Core tests include malformed/missing/wrong fields, zero/oversized PID, extra fields, oversized bytes, symlink, directory and mode-zero unreadability. All preserve capsule bytes, expose unknown through scan/inspect, refuse foreign removal and allow a dirty restored copy. Tests also repair the lease while the owner runs, observe normal-close inactivity, permit own-session dismissal and hold preparation while a foreign lease becomes unverified before commit. Schema and current-process probes are covered; Windows remains explicitly unqualified and conservative.

The public dismissal workflow uses a real separate owner process, its saved LED schematic and an independent observer running RC. It transitions active→unknown→active→inactive, checks consistent scan/inspection/failed-job metadata, restores the unknown-owner snapshot through a fresh copy client, and confirms original source/capsule preservation. Native and headless observer paths use the same dispatcher. The existing process-crash workflow separately checks a retained valid lease after SIGKILL. No numerical model, solver, circuit capacity, source/capsule format or application command changes.

See [behavior/API rules](../docs/recovery-ownership.md) and [validation receipt](../docs/validation/recovery-ownership-validation.json). Repeated recovery latency, full physical input/accessibility, platform/distribution, hostile filesystem and power-loss guarantees remain separate.
