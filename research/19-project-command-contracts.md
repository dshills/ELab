# Project lifecycle and file command contracts

The hobbyist workflow already supports New, Save and Open through shared user/agent commands. This checkpoint fills a discovery gap: an agent could see typed inputs but could not discover important file/state semantics from the eight commands themselves. The implementation adds on-demand contracts rather than enlarging ordinary discovery.

The contracts cover `project.inspect`, `project.clear`, waiting/start Save/Open, retained work inspection and exact cancellation. They describe dirty/discard and generation guards; captured saves and later edits; disk-conflict protection; Open supersession; cancellation before publication; historical association; terminal versus live readiness; consumed retry keys after admitted failure; literal/null paths; versions/size limits; and eight retained/shared-worker slots. All existing command identities, models and project formats remain.

A repaired-file experiment demonstrates why retry guidance matters. The original admitted missing-file Open fails. After the file is created, the same request key still returns its original owned failure. A new key performs the new read. Another controlled experiment holds a Save at publication: cancellation refuses, New remains responsive, and the old artifact finishes without associating with the new document. Detailed deadline metadata is checked against the actual admitted worker context.

The dedicated `--project-contract-suite` records fourteen observed snapshots, the complete admission-time save document, historical job metadata, three refusal codes, the destination contents after the refused save, all eight schemas and every public command. It captures an RC circuit with a kept recording, edits R1 after Save admission, protects an outside writer, explicitly overwrites, refuses terminal cancellation/malformed Open, clears without rewriting the file, and reopens fresh/paused through start and waiting commands. File-race boundaries remain controlled tests rather than timing assumptions. Fourteen negative report cases cover absent or altered contracts, bounds, observers, failures, evidence, captured data and fresh time.

The initial test harness stepped directly after asynchronous Restart and then retained the example's running pause preference. The final sequence explicitly pauses after loading the example and waits for initialization. Those failures are test setup evidence; no runtime timing, accuracy, model or work bound was relaxed. An earlier blocked-publication test also used a helper that waits for settlement; it now dispatches directly while the intentional barrier is held.

The first four-adapter comparison correctly flagged two different job counters: native startup configures recovery through the same public job mechanism. All other normalized calls and eight schemas matched. Final comparison requires each inspect/cancel call to target its observed admission/overwrite job, then maps only those validated targets to roles. Actual IDs remain in the report; a shifted-counter regression must pass and an unrelated target must fail, including self-comparison. Review also adds a direct byte check that the refused save preserved the outside writer. This is harness/evidence work; runtime file semantics are unchanged.

Read-only inventory of all **162** commands finds **98** with a scoped semantic contract and **64** without one. This counts annotations, not complete behavior qualification: several unscoped schemas already include bounds/examples, and a contract's presence does not establish native or event coverage. Remaining groups include captured output/preview, import/recovery mutations, recorded playback, history, appearance/display and lifecycle/navigation helpers. P0 remains **17 implemented /10 partial**.

See [client-facing contracts](../docs/project-command-contracts.md) and the [validation receipt](../docs/validation/project-contracts-validation.json). Complete event ordering, physical/native/accessibility, universal filesystem and release/participant gates remain open.

Final qualification passes all four adapters with **44 project workflow checks**, **56 observed snapshots**, **twelve retained project files** and **27,596 accompanying numerical checks**. All eight expanded schemas match; ordinary discovery remains equal to the recorded pre-change response. Admission/overwrite file hashes and loaded components match independently reviewed bytes. Raw and lossless-gzip typed reviews produce identical results.

The normal build and final full quality gate pass: formatting/imports/Staticcheck, 22 Python tests, root/native race and vet. Final build took 1.705 s and quality 129.803 s; the corrected public run took 48.020 s. The identical runtime candidate had already passed all 45 packaged smoke stages in 38.673 s. Both canonical 0.105/preserved 0.104 app trees retain every prior byte and mode; the separately hashed 0.109 private candidate is not promoted. All 671 frozen inputs and the pinned Vellum SDK verify after qualification. The continuing PRD/repository goal remains active.
