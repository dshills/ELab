# Text editing and application shortcuts /216

October 23, 2026. Repair of existing keyboard behavior; no new electronics,
commands, components or file formats.

The retained-widget check routes real key events through production search and
value-entry nodes and ELab's application command registry. With the macOS key
profile, pressing Command-Z in a freshly focused `1 kΩ` value entry changes its
private text to an empty string. The circuit itself does not change. Direct
dependency tests reproduce the same problem for empty history and repeated Undo
at the oldest entry, including Unicode text and selection.

The prepared Cogent text history returned an empty record when no Undo was
available. It now returns no record. This preserves the field's initial text,
cursor and selection at that boundary. Normal Undo/Redo, repeated boundaries and
a new edit after Undo retain their existing behavior. Compatibility stage 0109
records the exact input/output hashes and includes the regression test. The
original stage sequence and prior SDK archives remain preserved.

The fixture also checks Backspace, Delete, Left, Right and Escape while editing.
Text Undo/Redo must remain local, even when circuit history is available. After
Tab moves to a supported non-editor control, the same Command-Z and
Shift-Command-Z must reach ELab's real application Undo/Redo commands; those
positive controls prevent a silent no-op from passing as keyboard ownership.

Earlier offscreen helpers supplied `key.Meta`, an enum index, where a modifier
bit mask was required. Together with the offscreen default Linux key profile,
that exercised Control-A instead of the intended macOS Command-A. The helpers
now use `1 << key.Meta`, explicitly select MacStandard after mounting and restore
the preceding global profile at cleanup. Existing assertions remain intact.
This does not retroactively qualify earlier tests as native Mac key events.

An initial attempt to mount the custom schematic in the manual backend was
refused as an unsupported custom extension. The final fixture mounts supported
production text controls and a neutral document-focus button. It does not claim
to mount the schematic or qualify a newly launched AppKit event loop. Initial
test-constant, layout-constraint and key-profile mistakes are retained separately
as harness errors rather than application defects.

Two SDK preparation tests also assumed compatibility stage 0105 was the last
stage, although elab8 already contained stages 0106–0108. A check using the old
manifest reproduces those stale expectations. The repaired tests locate stages
0104/0105 by their identifiers, retain their original checksum assertions and
require the complete ordered sequence 0001–0109. All 30 preparation tests pass.

A supplemental race run of every upstream Core test is not green: legacy
render/menu tests report concurrent scene, stage and paint access. A read-only
overlay restoring the exact old text-field implementation also fails, with 26
of the same failing test names and one different race-affected test on each
run. The race counts and differing failures are preserved; this is evidence of
an existing broader test/runtime concern, not a claim that every failure has
been attributed. The focused text/IME/native-edit regression passes separately.
No global renderer repair is included in this narrow text-history change.
