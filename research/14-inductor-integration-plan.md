# Ideal inductors: integration plan

October 16, 2026. Status: implementation in progress; not released. Private preliminary bundles exist for testing. This advances the expanded-parts P1 item in [the PRD](07-product-requirements.md), with the same live, editable and agent-operable workflow. The qualified application remains **0.103.0 /118**. Inductors are now present in the working source, but release qualification, public/native workflows and physical output inspection remain incomplete. This document does not establish that inductor support has shipped or replace the outstanding P0 acceptance gates.

The intended result is a two-terminal ideal inductor that a hobbyist can place, wire, rotate, edit, give a signed initial current, probe, run live, Verify, save/reopen and export. Three experiments should establish its usefulness: RL current buildup/decay, RLC ringing, and inductive switching with a flyback diode. Native controls and external agents must use the same validated commands and produce the same accepted state.

## Model and workflow contract

- Use a versioned ideal model, tentatively `ideal-inductor.v1`, with inductance in H, voltage pin 1 minus pin 2, current positive into pin 1/out of pin 2, and stored energy `L I² / 2`. Explicitly describe omitted winding resistance, saturation, mutual coupling, parasitic capacitance, heating, ratings and physical part identity. An external resistor supplies winding/load resistance in the experiments.
- Start with zero current by default. A saved, undoable, per-component signed initial-current command should accept unit-bearing text and reset-to-default. Verify needs an explicit scenario override with documented precedence. Existing capacitor startup and global initial-voltage semantics must retain their meanings.
- Proposed defaults are 10 mH and four inductors per network. Numeric inductance/current domains must be qualified and published before palette exposure; they are engineering limits, not physical ratings. Retain current global part/node/source limits, ±30 V node envelope and cancellation/integration work budgets.
- Topology/value/initial-current edits follow existing restart/stale rules. Move/rotate/view operations preserve accepted current and charge. Source and switch actuation at the same accepted time preserve both capacitor voltage and inductor current; a failed, canceled or superseded solve publishes neither partial memory nor a new time.
- Show signed voltage/current, energy and provenance through ordinary selection, terminal/net readings, pins and scope probes. Current cues must include the new branch in the existing unique-wire-current calculation. Timing measurements and captured comparisons continue to operate on stored samples with their existing resolution limits.

## Initial kernel proposal (superseded during implementation)

The current [network kernel](../workbench/mixed.go) stores node voltages and source branch currents in `mixedState.x`, with separate capacitor voltage memory in `capV`. Its zero-time solve gives capacitors explicit voltage constraints; its time step uses backward-Euler conductances. [Input and edge processing](../workbench/mixed_transient.go) already recomputes algebraic states at the same time while preserving capacitor memory.

An inductor needs a persistent branch-current unknown. A candidate ordering is **nodes, voltage-source currents, inductor currents, zero-time capacitor currents**. Appending temporary capacitor currents last keeps the persistent inductor indices stable when a positive time step removes capacitor constraint rows. The branch contributes `+I` and `−I` to its two node equations.

At a positive time step, stamp:

```
V1 - V2 - (L / dt) (I - I_old) = 0
```

At startup or a same-time algebraic recomputation, constrain `I = I_old`; use the configured initial current only for a fresh run. Capture prior currents once from the accepted guess before Newton retries or alternate seeds. Do not obtain the “old” current from a changing Newton iterate. Keeping persistent current in `x` may let the existing private-state clone copy it safely without a second mutable memory array; that proposal still needs cancellation, retry and topology tests.

The zero-time current-constraint residual is in amperes, unlike the positive-time inductor row's voltage residual. Preserve the appropriate current/voltage tolerances rather than applying the existing voltage-row tolerance indiscriminately. Update every dimension, branch-index and seed builder consistently, including [grounded startup guesses](../workbench/mixed_startup.go). Current constraints do not provide a guessed node voltage or justify a fabricated ground/leakage path.

The present no-capacitor shortcut takes one algebraic solve, and the adaptive comparison checks capacitor voltages. Both need explicit inductor treatment: compare full/two-half-step currents, relevant node voltages and stored energy, using dimensional tolerances. Pure RL circuits must enter dynamic stepping even with no capacitor. Underdamped LC motion creates an additional hazard: large backward-Euler steps can erase oscillation while full/half results look deceptively similar. Establish and test an oscillation-aware initial/maximum step policy; a small difference between two over-damped numerical answers is insufficient evidence of accuracy. The timestep policy is an unresolved design/validation item, not a claimed bound.

Power accounting must include the inductor's stored-energy change and backward-Euler numerical damping. For an accepted step the latter is `L (I - I_old)² / (2 dt)`. At a same-time solve, instantaneous `V I` participates without a finite energy difference. Preserve the meaning of the existing conservation fields; report finite results and reject out-of-envelope states atomically.

## Current implementation and numerical decisions

The working source uses **`elab.rlc-mna-radau5.v1`** and **`RLC network transient`** whenever L is present. Earlier circuits retain their existing equations and engine identities. The initial backward-Euler and subsequent trapezoidal proposals are design history. The retained mixed RC/NPN/coil regression exposed inadequate trapezoidal behavior near controlled-current constraints; TR-BDF2 alone also failed its work budget. Three-stage Radau IIA collocation, with explicit Newton voltage-correction convergence, passes that regression and the independent simpler references without changing their tolerances. The [SciPy method documentation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.Radau.html) describes the order-five Radau IIA family; ELab derives its coefficients by integrating the Lagrange polynomials at `(4−√6)/10`, `(4+√6)/10`, and `1`. The implementation is in Go and does not depend on SciPy.

- Persistent vector: nodes, source currents, L currents, C currents. Immutable integration history contains only C voltage and L current. Algebraic L voltages and C currents are readings, not recursively integrated derivative history.
- Each of the three stages enforces physical device/source equations and KCL. Its L rows impose `I_i − I_old = (h/L) Σ A_ij V_Lj`; C rows impose `V_i − V_old = (h/C) Σ A_ij I_Cj`. The last stage is the accepted endpoint. At zero time, impose accepted/configured L current and C voltage. In steady DC, L voltage is zero and its current is solved.
- Current-only cuts at startup require consistent signed initial currents. Group non-L current paths, check their external L-current balance, and replace a redundant summed KCL row with its differentiated relation `Σ(sign × V/L)=0`. This determines series-coil voltage division and floating conductive-island voltages. Physical KCL remains measured from the original device equations. No leakage or artificial elapsed time is introduced.
- Compare one full step with two half steps, accepting the latter. Check L currents, every node voltage and C voltage. The comparison is conservative; it is not divided by a nominal differential-order factor for algebraic variables. With C, node absolute tolerance is 50 nV, current absolute tolerance 100 pA and relative tolerance 0.5 ppm. Without C, they are 500 nV, 5 nA and 5 ppm. C-voltage tolerance is 50 nV plus 0.5 ppm. Grow with a conservative cubic controller and retain the LC ceiling `0.1 sqrt(min L × min C)/(number L × number C)`. That ceiling guards aliasing, not every possible network mode.
- Newton requires both the residual criteria and a voltage correction within `1e-10 V + 1e-11 |node voltage|`. Residuals alone can accept an inaccurate collector voltage when junction output conductance is tiny. Scaled storage-row tolerances include the magnitudes of both node voltages, so near-equal rail voltages do not demand precision below subtraction roundoff.
- L/C power is instantaneous `V × I`, with physical KCL and instantaneous power residuals. `numerical_damping_w` retains the legacy backward-Euler compensation meaning and is zero for this engine; it does not assert zero Radau integration loss. Actual LC energy and phase are checked independently against unchanged 1 pJ /1 mV /10 µA limits over 60 ms. A small instantaneous power residual alone does not prove time-integration accuracy.
- LED startup exposed two numerical floors: fixed absolute KCL tolerance could accept arbitrary low-current LED voltage, and fixed current-domain bisection could not resolve the model's `Is=1e-20 A` knee. Only L networks use the same forward LED equation solved in junction voltage, its forward one-sided Jacobian at zero, local KCL tolerance `1e-30 + 1e-12 Σ|Jacobian coefficient × unknown|`, and minimum internal step **1e-28 s**. Public sample bounds, ±30 V nodes and 512-attempt/100 ms output budgets remain. The legacy LED/internal-step path is unchanged.
- Every collocation Newton iteration checks the same output wall deadline. Private trial states contain only unknown/storage vectors; full readings are constructed after the entire output interval succeeds. Coupled elimination skips zero updates, with the original dense arithmetic path retained for legacy circuits. Actual coupled-matrix solutions are compared against the dense solver. No tolerance, gate or work limit was relaxed to obtain passing results.
- A prior conditioning-based voltage-tolerance relaxation degraded flyback tail voltage by about 9 mV and was removed.

Focused tests cover RL exponential buildup/decay and signed/tiny startup, series/parallel coils, floating source/resistor islands, circulating current, free-LC phase/energy, three RLC damping regimes, and large-request refusal. The NMOS flyback example agrees with independent scalar RK4 through turn-off and a separately checked off-tail equilibrium. A missing diode refuses without publishing partial time. Series LED/coil startup agrees with independent time-of-flight quadrature from 1 µs through 20 ms, plus inductance/time scaling at 1 µH, 1 mH and 100 H. Shared commands cover Verify isolation, corruption refusal, save/fresh-service reopen, event continuity, and canceled/superseded work. Tiny signed 1 pA startup is seeded exactly; incompatible pA-scale cutset currents refuse. These checks do not replace the release gates below.

The source adds `inductor.initial.set`, optional `initial_current_a` on L, optional `inductor_initials` on Verify settings/requests, and `inductors` in network results. Values are 1 µH–100 H; startup current is signed ±1 A, default zero, with at most four L and existing global bounds. Shared Verify input uses a local schema registry definition to keep ordinary discovery inside 64 KiB. Native/export coil geometry is shared; `rl`, `rlc` and `flyback` use ordinary protected `example.load`.

## Operating point and topology

Live initialization with a configured current differs from steady DC. [DC sweeps](../workbench/dc_sweep.go) currently open capacitors in a private plan; their inductor plan must instead impose zero voltage and solve the branch current. A transient inductor directly across an ideal source can be valid while its DC operating point is inconsistent. Apply analysis-specific checks, with explicit diagnostics for indeterminate ideal loops/cutsets and incompatible initial currents. Avoid a blanket static restriction that silently substitutes one analysis for the other.

Review floating islands, parallel/series inductors, capacitor/inductor loops, source/inductor loops, all-zero input, nonzero startup current, singular zero-residual guesses, and switching with/without a recirculation path. An interrupting switch can demand a node voltage beyond the declared envelope. Keep the last accepted state and explain the failure; a flyback diode should produce a separately validated finite recirculation solution. Current limits and finite SPST off resistance remain explicit model properties.

## Mixed-device regression and repair evidence

`TestInductorCoupledNPNGateCapacitorStepRefinement` retains the same NPN-driven flyback circuit, 10 kΩ drive, explicit 1 µF base capacitor and complete period at 1 ms /0.5 ms /0.25 ms outputs. Trapezoidal variants exhausted work near 1.273 ms; TR-BDF2 advanced farther but also exhausted the unchanged limit. The coupled Radau engine and voltage-correction convergence pass all three intervals. The fixture was not skipped, simplified or given larger budgets.

A separate reduced reference pins the published model constants and integrates the base equation with RK4. In the early forward-active region, it derives coil current from the collector transport relation and collector voltage from its derivative/KVL; checks include 1.273 ms. A separate steady reference and coupled base/coil RK4 with inverse Shockley clamp cover the high-phase equilibrium, ideal edge and 1 µs–5 ms turn-off interval. The first 1 ps of the independent off reference is bounded by the ±30 V envelope to at most 30 pA current uncertainty. These checks supplement full-period refinement rather than substituting it for an independent reference.

Additional tests verify collocation moments, fifth-order fixed-step RL convergence, the coupled Jacobian against finite differences, zero-update elimination against the dense solver, and an in-stage deadline refusal that preserves accepted state. Race instrumentation initially hit the 100 ms deadline; skipping zero elimination updates and avoiding full result construction for trial stages restore passing focused race checks. Recorded work-envelope tests measure actual per-output attempts/time under the same production limits. Final complete gates and rebuilt/public/native evidence must follow the engine change; preliminary TR bundles and earlier smoke results do not qualify the Radau binary.

## Evidence required before shipping

1. Independent RL step and signed-current decay references, including nonzero/reversed initial current; voltage/current/energy and conservation tolerances stated in SI units.
2. Independent underdamped, critically damped and overdamped RLC references. Include a high-Q/large-output-step case designed to catch artificial numerical loss of ringing, plus default/half/quarter-step refinement and explicit budget refusals.
3. A switched inductive load with a diode return path, using an independent ODE/reference calculation and both accepted event sides. Compare current continuity, stored energy, signed diode/source currents and clamp voltage. A missing-path case must preserve prior physics on failure.
4. Mixed RC/NPN/MOSFET fixtures, same-time source/switch/wiper work, canceled/superseded updates, cold/warm startup and DC operating-point distinctions. Keep existing frozen reference checks passing.
5. Native blank construction/value/startup/probe operation versus agents; physical default-window inspection; rotation/label/pin/route containment in native and exported output. Preserve all existing commands' behavior and identities.
6. Save/fresh-process reopen, edited example origin, recovery/undo, Verify capture/CSV, strict corrupt/foreign/missing-model/result rejection and actual prior-version project/capture reopen with original bytes unchanged.
7. Final lint/import/vet/race, packaged GPU/UI/protected-close smoke, four-client reference and new-device workflows, independent electrical suite and transport-inclusive timing evidence on recorded hardware. Visible-latency, screen-reader, clean distribution, participant and physical-print acceptance remain separately open unless actually performed.

The remaining implementation work must complete the integrated workflows and release evidence above before promoting the part into the qualified application. Uncertainty about numerical behavior should produce stronger tests and explicit diagnostic contracts.
